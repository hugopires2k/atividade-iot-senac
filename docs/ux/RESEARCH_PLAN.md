# User research (needed: >= 5 interviews or >= 20 survey answers)

**Nothing in this file is data yet.** The persona below is a hypothesis to validate; replace it with what people actually answer.
Save the raw answers (form export, interview notes) in this folder as evidence.

## Hypothesis
- Persona: *to be defined from the research* (who needs to know the temperature, humidity and light of a place while away from it?).
- Value proposition: *a place's conditions on your phone, with a clear warning when data stops arriving or a sensor fails.*

## Survey questions (Google Forms, about 5 min)
1. What do you need to monitor (room, plants, storage, server rack, other)? How do you do it today?
2. How often do you check it? What happens when something goes wrong?
3. Which value matters most: temperature, humidity or light? What range is "a problem" for you?
4. How would you like to be warned (push, e-mail, WhatsApp, none)?
5. Would you trust a reading if the app did not say how old it is? What should it show when there is no data?
6. Would you use this? How much would you pay per month, if anything?

## Journey (draft, to complete with the answers)
Worry -> open the app -> see current values and "last contact" -> understand if it is a problem -> act.
